           SMARTBIDS — ESTRUCTURA Y DICCIONARIO DE BASE DE DATOS ACTUAL

Fecha de actualización: 28 de Octubre de 2026

################################################################################
1. ESQUEMA "core" — ENTIDADES PRINCIPALES, USUARIOS Y SEGUIMIENTO
################################################################################
Este esquema gestiona el ciclo de vida del usuario, las organizaciones asociadas,
las preferencias comerciales, el cumplimiento normativo (Ley N° 21.719 - ARCOP)
y las interacciones privadas con licitaciones.

--------------------------------------------------------------------------------
* TABLA: "core"."suscriptor"
  - Modelo Django: Suscriptor
  - Descripción: Almacena la identidad de los usuarios registrados en SmartBids,
    su token de sesión única activa, vinculación a Firebase Auth, consentimiento
    legal informado y estado operativo de la cuenta.
  - Conexiones:
    * Clave Foránea: codigo_estado -> "config"."estado_suscriptor" (Estado del usuario: Habilitado, Bloqueado, Admin).
    * Clave Foránea: sus_rut_empresa -> "core"."empresa" (Empresa a la que pertenece el suscriptor).
    * Tablas que apuntan a ella:
      <- "core"."preferencia" (id_suscriptor)
      <- "core"."smartbids_seguimiento_licitacion" (usuario)
      <- "core"."smartbids_notificacion_licitacion" (usuario)
      <- "core"."smartbids_solicitud_arcop" (id_suscriptor)
  - Campos principales: id_suscriptor (PK, BigAutoField), firebase_uid (VARCHAR(128) UNIQUE),
    token_sesion (VARCHAR(128)), sus_nombre1, sus_nombre2, sus_apellido1, sus_apellido2,
    sus_nombre_social, sus_iniciales, fecha_registro, fecha_actualizacion,
    consentimiento_terminos_fecha (TIMESTAMPTZ - Fecha y hora de aceptación de Términos y Privacidad),
    consentimiento_terminos_version (VARCHAR(20) - Versión legal aceptada, ej: 'v1.0'),
    consentimiento_marketing (BOOLEAN - Consentimiento opcional de comunicaciones).

--------------------------------------------------------------------------------
* TABLA: "core"."empresa"
  - Modelo Django: Empresa
  - Descripción: Entidad tributaria o persona jurídica asociada a los suscriptores
    para el perfilamiento y postulación a licitaciones públicas.
  - Conexiones:
    * Clave Foránea: emp_codigo_comuna -> "catalog"."comuna" (Comuna de la casa matriz).
    * Clave Foránea: emp_actividad_economica -> "catalog"."actividad_economica" (Giro SII).
    * Tablas que apuntan a ella:
      <- "core"."suscriptor" (sus_rut_empresa)
  - Campos principales: emp_rut (PK), emp_razon_social, emp_nombre_fantasia,
    emp_iniciales, emp_contacto_correo, emp_direccion, emp_contacto_nombre,
    emp_contacto_telefono, emp_codigo_comuna (FK).

--------------------------------------------------------------------------------
* TABLA: "core"."preferencia"
  - Modelo Django: Preferencia
  - Descripción: Guarda los criterios de búsqueda, filtros de mercado y perfil
    comercial calibrado del suscriptor para el algoritmo de recomendación y match.
  - Conexiones:
    * Clave Foránea: id_suscriptor -> "core"."suscriptor" (Suscriptor dueño del filtro).
  - Campos principales: id_preferencia (PK), pref_comunas (array códigos comuna),
    pref_tipo_licitacion (array tipos), pref_ucom (array unidades de compra),
    pref_palabras_claves (array palabras clave crudas), pref_palabras_claves_norm (array normalizado NLP),
    pref_productos (array códigos ONU UNSPSC).

--------------------------------------------------------------------------------
* TABLA: "core"."smartbids_seguimiento_licitacion"
  - Modelo Django: SeguimientoLicitacion
  - Descripción: Licitaciones marcadas como favoritas o puestas en seguimiento
    activo por los usuarios ("Mis Licitaciones").
  - Conexiones:
    * Clave Foránea: usuario -> "core"."suscriptor" (Usuario que sigue la licitación).
    * Clave Foránea: licitacion -> "procurement"."licitacion" (Licitación monitoreada).
    * Tablas que apuntan a ella:
      <- "core"."smartbids_notificacion_licitacion" (seguimiento)
  - Campos principales: id (PK, BigAutoField), usuario (FK), licitacion (FK),
    estado_actual (publicada, preguntas, ofertas, cerrada), seguimiento_activo (BOOLEAN),
    creado_en, actualizado_en, dejado_de_seguir_en, cerrada_en.
  - Restricciones: UniqueConstraint(usuario, licitacion) para evitar duplicados.

--------------------------------------------------------------------------------
* TABLA: "core"."smartbids_notificacion_licitacion"
  - Modelo Django: NotificacionLicitacion
  - Descripción: Bitácora de avisos generados ante cambios de estado, nuevas preguntas
    o publicación de actas en las licitaciones en seguimiento.
  - Conexiones:
    * Clave Foránea: usuario -> "core"."suscriptor" (Destinatario del aviso).
    * Clave Foránea: licitacion -> "procurement"."licitacion" (Licitación causante).
    * Clave Foránea: seguimiento -> "core"."smartbids_seguimiento_licitacion".
  - Campos principales: id (PK, BigAutoField), usuario (FK), licitacion (FK),
    seguimiento (FK), estado_anterior, estado_nuevo, mensaje, leida (BOOLEAN), creado_en.

--------------------------------------------------------------------------------
* TABLA: "core"."smartbids_licitacion_documento"
  - Modelo Django: LicitacionDocumento
  - Descripción: Registro de bases administrativas, técnicas y anexos descargables
    asociados a cada licitación pública.
  - Conexiones:
    * Clave Foránea: licitacion -> "procurement"."licitacion".
  - Campos principales: id (PK), licitacion (FK), titulo, url, fecha_publicacion.

--------------------------------------------------------------------------------
* TABLA: "core"."smartbids_licitacion_pregunta"
  - Modelo Django: LicitacionPregunta
  - Descripción: Registro del foro oficial de aclaraciones y respuestas entre
    proveedores y el organismo comprador de Mercado Público.
  - Conexiones:
    * Clave Foránea: licitacion -> "procurement"."licitacion".
  - Campos principales: id (PK), licitacion (FK), pregunta, respuesta, fecha_pregunta, fecha_respuesta.

--------------------------------------------------------------------------------
* TABLA: "core"."smartbids_solicitud_arcop" (NUEVA - Ley N° 21.719)
  - Modelo Django: SolicitudArcop
  - Descripción: Bitácora formal y auditoría legal de solicitudes de ejercicio de
    Derechos ARCOP (Acceso, Rectificación, Cancelación / Supresión, Oposición y
    Portabilidad de datos personales) conforme a los Artículos 8, 9 y 10 de la
    Ley N° 21.719 de Protección de Datos Personales, con plazo de respuesta de 15 días hábiles.
  - Conexiones:
    * Clave Foránea: id_suscriptor -> "core"."suscriptor" (ON DELETE CASCADE).
  - Campos principales: id (PK, BigAutoField), id_suscriptor (FK),
    tipo_derecho (VARCHAR(20): ACCESO, RECTIFICACION, CANCELACION, OPOSICION, PORTABILIDAD),
    detalle (TEXT - Explicación de la solicitud del usuario),
    estado (VARCHAR(20): PENDIENTE, PROCESADO, RECHAZADO),
    creado_el (TIMESTAMPTZ - Fecha y hora de solicitud),
    respondido_el (TIMESTAMPTZ - Fecha y hora de resolución formal),
    observaciones (TEXT - Dictamen o detalle técnico/legal de respuesta).


################################################################################
2. ESQUEMA "procurement" — COMPRAS PÚBLICAS Y LICITACIONES DEL ESTADO
################################################################################
Contiene los procesos contractuales de compra pública extraídos y sincronizados
desde la plataforma de Mercado Público (ChileCompra).

--------------------------------------------------------------------------------
* TABLA: "procurement"."licitacion"
  - Modelo Django: Licitacion
  - Descripción: Ficha maestra y cabecera de cada proceso de compra pública. Contiene
    fechas críticas, montos estimados, organismo licitante y estado actual.
  - Conexiones:
    * Clave Foránea: lic_codigo_ucom -> "procurement"."unidad_compra".
    * Clave Foránea: lic_estado -> "catalog"."estado_licitacion".
    * Tablas que apuntan a ella:
      <- "procurement"."licitaciones_productos" (lic_codigo)
      <- "core"."smartbids_seguimiento_licitacion" (licitacion)
      <- "core"."smartbids_notificacion_licitacion" (licitacion)
      <- "core"."smartbids_licitacion_documento" (licitacion)
      <- "core"."smartbids_licitacion_pregunta" (licitacion)
  - Campos principales: lic_codigo (PK, ej: 1057-2-LP24), lic_nombre,
    lic_descripcion, lic_fecha_cierre, lic_hora_cierre, lic_toma_razon,
    lic_codigo_ucom (FK), lic_fecha_public, lic_fecha_preguntas, lic_fecha_respuestas,
    lic_tipo_licitacion, lic_moneda, lic_presupuesto, lic_items_cantidad,
    lic_codigos_producto (array), lic_diccionario_palabras (array), lic_texto,
    lic_url, lic_plazo, lic_estado (FK).

--------------------------------------------------------------------------------
* TABLA: "procurement"."unidad_compra"
  - Modelo Django: UnidadCompra
  - Descripción: Unidad operativa, departamento o sucursal pública que gestiona
    la licitación dentro de un organismo estatal.
  - Conexiones:
    * Clave Foránea implícita / lógica: ucom_codigo_organismo -> "catalog"."organismo".
    * Clave Foránea implícita / lógica: ucom_codigo_comuna -> "catalog"."comuna".
    * Tablas que apuntan a ella:
      <- "procurement"."licitacion" (lic_codigo_ucom)
  - Campos principales: codigo_unidad_compra (PK, BigIntegerField), ucom_activo,
    ucom_codigo_ambito, ucom_codigo_organismo, ucom_rut, ucom_direccion,
    ucom_codigo_comuna, ucom_descripcion.

--------------------------------------------------------------------------------
* TABLA: "procurement"."licitaciones_productos"
  - Modelo Django: LicitacionesProductos
  - Descripción: Detalle desagregado de los bienes y servicios licitados en cada proceso
    (asociación de códigos de producto UNSPSC a cada licitación).
  - Conexiones:
    * Clave Foránea: lic_codigo -> "procurement"."licitacion".
    * Clave Foránea implícita / lógica: codigo_producto -> "catalog"."producto".
  - Campos principales: pk (PK compuesta: lic_codigo + codigo_producto), lic_codigo (FK),
    codigo_producto (VARCHAR(20)).


################################################################################
3. ESQUEMA "catalog" — TABLAS MAESTRAS Y CATÁLOGOS NORMALIZADOS
################################################################################
Estructuras dimensionales y maestras para garantizar la integridad territorial,
institucional y taxonómica de compras públicas en Chile.

--------------------------------------------------------------------------------
* TABLA: "catalog"."region"
  - Modelo Django: Region
  - Descripción: División político-administrativa de las 16 regiones de Chile.
  - Conexiones:
    <- "catalog"."provincia" (codigo_region)
  - Campos principales: codigo_region (PK, VARCHAR(2)), nombre_region,
    region_3l (VARCHAR(3)), orden (PositiveSmallIntegerField para ordenación de Norte a Sur).

--------------------------------------------------------------------------------
* TABLA: "catalog"."provincia"
  - Modelo Django: Provincia
  - Descripción: Provincias que conforman cada región de Chile (56 provincias).
  - Conexiones:
    * Clave Foránea: codigo_region -> "catalog"."region".
    * Tablas que apuntan a ella:
      <- "catalog"."comuna" (codigo_provincia)
  - Campos principales: codigo_provincia (PK, VARCHAR(3)), nombre_provincia, codigo_region (FK).

--------------------------------------------------------------------------------
* TABLA: "catalog"."comuna"
  - Modelo Django: Comuna
  - Descripción: Comunas de Chile (346 comunas, nivel territorial de organismos y empresas).
  - Conexiones:
    * Clave Foránea: codigo_provincia -> "catalog"."provincia".
    * Tablas que apuntan a ella:
      <- "catalog"."organismo" (org_codigo_comuna)
      <- "catalog"."proveedor" (prov_codigo_comuna)
      <- "core"."empresa" (emp_codigo_comuna)
  - Campos principales: codigo_comuna (PK, VARCHAR(5)), nombre_comuna, codigo_provincia (FK).

--------------------------------------------------------------------------------
* TABLA: "catalog"."pais"
  - Modelo Django: Pais
  - Descripción: Catálogo de países de origen de proveedores y organismos.
  - Conexiones:
    <- "catalog"."proveedor" (prov_codigo_pais)
  - Campos principales: pais_codigo (PK, BigAutoField), pais_nombre, pais_codigo_iso2, pais_activo.

--------------------------------------------------------------------------------
* TABLA: "catalog"."sector"
  - Modelo Django: Sector
  - Descripción: Sectorización del Estado (Salud, Educación, Municipalidades, Obras Públicas, etc.).
  - Conexiones:
    <- "catalog"."organismo" (org_codigo_sector)
  - Campos principales: codigo_sector (PK, VARCHAR(3)), nombre_sector.

--------------------------------------------------------------------------------
* TABLA: "catalog"."organismo"
  - Modelo Django: Organismo
  - Descripción: Instituciones y ministerios públicos compradores del Estado.
  - Conexiones:
    * Clave Foránea: org_codigo_comuna -> "catalog"."comuna".
    * Clave Foránea: org_codigo_sector -> "catalog"."sector".
  - Campos principales: codigo_organismo (PK, BigIntegerField), org_nombre,
    org_sigla, org_rut, org_reclamos, org_codigo_comuna (FK), org_codigo_sector (FK), org_direccion.

--------------------------------------------------------------------------------
* TABLA: "catalog"."tipo_licitacion"
  - Modelo Django: TipoLicitacion
  - Descripción: Modalidades de licitación pública según montos en UTM (L1, LE, LP, LQ, LR, etc.).
  - Conexiones:
    * Clave Foránea: codigo_cat_licitacion -> "catalog"."categoria_licitacion".
    * Clave Foránea: codigo_tramo_licitacion -> "catalog"."tramo_licitacion".
  - Campos principales: codigo_tipo_licitacion (PK, VARCHAR(2)), glosa,
    codigo_cat_licitacion (FK), codigo_tramo_licitacion (FK), activo (BOOLEAN).

--------------------------------------------------------------------------------
* TABLA: "catalog"."estado_licitacion"
  - Modelo Django: EstadoLicitacion
  - Descripción: Estados oficiales de un proceso de compra pública en Mercado Público
    (Publicada, En Preguntas, Cerrada, Adjudicada, Desierta, Revocada).
  - Conexiones:
    <- "procurement"."licitacion" (lic_estado)
  - Campos principales: codigo_estado_licitacion (PK, SmallAutoField), nombre_estado_licitacion (VARCHAR(50) UNIQUE).

--------------------------------------------------------------------------------
* TABLA: "catalog"."tramo_licitacion"
  - Modelo Django: TramoLicitacion
  - Descripción: Tramos de montos expresados en Unidades Tributarias Mensuales (UTM)
    (menor a 100 UTM, 100 a 1.000 UTM, 1.000 a 2.000 UTM, etc.).
  - Conexiones:
    <- "catalog"."tipo_licitacion" (codigo_tramo_licitacion)
  - Campos principales: codigo_tramo_licitacion (PK, SmallAutoField), nombre_tramo_licitacion.

--------------------------------------------------------------------------------
* TABLA: "catalog"."categoria_licitacion"
  - Modelo Django: CategoriaLicitacion
  - Descripción: Clasificación genérica (Pública, Privada, Trato Directo).
  - Conexiones:
    <- "catalog"."tipo_licitacion" (codigo_cat_licitacion)
  - Campos principales: codigo_cat_licitacion (PK, SmallAutoField), nombre_cat_licitacion.

--------------------------------------------------------------------------------
* TABLA: "catalog"."ambito"
  - Modelo Django: Ambito
  - Descripción: Ámbito geográfico o normativo del proceso.
  - Campos principales: codigo_ambito (PK, VARCHAR(3)), nombre_ambito.

--------------------------------------------------------------------------------
* TABLA: "catalog"."unidad_medida"
  - Modelo Django: UnidadMedida
  - Descripción: Unidades de medida estandarizadas (Unidad, Metro, Kilo, Global, Mes, etc.).
  - Conexiones:
    <- "catalog"."producto" (codigo_unidad_medida)
  - Campos principales: codigo_unidad_medida (PK, VARCHAR(3)), nombre_unidad_medida.

--------------------------------------------------------------------------------
* TABLA: "catalog"."rubro_actividad"
  - Modelo Django: RubroActividad
  - Descripción: Macro-sectores y rubros de actividad comercial.
  - Conexiones:
    <- "catalog"."subrubro_actividad" (codigo_rubro)
  - Campos principales: codigo_rubro (PK, VARCHAR(2)), nombre_rubro.

--------------------------------------------------------------------------------
* TABLA: "catalog"."subrubro_actividad"
  - Modelo Django: SubrubroActividad
  - Descripción: Subclasificación de rubros comerciales.
  - Conexiones:
    * Clave Foránea: codigo_rubro -> "catalog"."rubro_actividad".
    * Tablas que apuntan a ella:
      <- "catalog"."actividad_economica" (codigo_subrubro)
  - Campos principales: codigo_subrubro (PK, VARCHAR(5)), nombre_subrubro, codigo_rubro (FK).

--------------------------------------------------------------------------------
* TABLA: "catalog"."actividad_economica"
  - Modelo Django: ActividadEconomica
  - Descripción: Catálogo oficial de giros y actividades económicas del SII.
  - Conexiones:
    * Clave Foránea: codigo_subrubro -> "catalog"."subrubro_actividad".
    * Tablas que apuntan a ella:
      <- "catalog"."proveedor" (prov_cod_actividad_economica)
      <- "core"."empresa" (emp_actividad_economica)
  - Campos principales: codigo_actividad (PK, VARCHAR(8)), nombre_actividad, afecto_iva,
    categoria_tributaria, disponible_internet, activo, codigo_subrubro (FK).

--------------------------------------------------------------------------------
* TABLA: "catalog"."grupo_producto"
  - Modelo Django: GrupoProducto
  - Descripción: Familias globales estándar de las Naciones Unidas (UNSPSC).
  - Conexiones:
    <- "catalog"."nivel1_producto" (codigo_grupo_producto)
  - Campos principales: codigo_grupo_producto (PK, VARCHAR(3)), nombre_grupo_producto.

--------------------------------------------------------------------------------
* TABLA: "catalog"."nivel1_producto"
  - Modelo Django: Nivel1Producto
  - Descripción: Segmentos de primer nivel de productos y servicios ONU.
  - Conexiones:
    * Clave Foránea: codigo_grupo_producto -> "catalog"."grupo_producto".
    * Tablas que apuntan a ella:
      <- "catalog"."producto" (nivel1)
  - Campos principales: codigo_nivel1 (PK, VARCHAR(10)), descripcion, codigo_grupo_producto (FK), activo.

--------------------------------------------------------------------------------
* TABLA: "catalog"."producto"
  - Modelo Django: Producto
  - Descripción: Catálogo normalizado de productos y servicios (código UNSPSC de 8 dígitos).
  - Conexiones:
    * Clave Foránea: nivel1 -> "catalog"."nivel1_producto".
    * Clave Foránea: codigo_unidad_medida -> "catalog"."unidad_medida".
  - Campos principales: codigo_producto (PK, VARCHAR(20)), descripcion, codigo_unidad_medida (FK),
    activo, nivel1 (FK), nivel2, nivel3, nivel4, glosa_nivel2, glosa_nivel3, glosa_nivel4.

--------------------------------------------------------------------------------
* TABLA: "catalog"."proveedor"
  - Modelo Django: Proveedor
  - Descripción: Registro histórico de empresas y personas naturales proveedoras de Mercado Público.
  - Conexiones:
    * Clave Foránea: prov_codigo_comuna -> "catalog"."comuna".
    * Clave Foránea: prov_codigo_pais -> "catalog"."pais".
    * Clave Foránea: prov_cod_actividad_economica -> "catalog"."actividad_economica".
  - Campos principales: pk (PK compuesta: prov_codigo_proveedor + prov_codigo_sucursal),
    prov_codigo_proveedor, prov_codigo_sucursal, prov_rut, prov_nombre, prov_razon_social,
    prov_direccion, prov_codigo_comuna (FK), prov_tamano, prov_codigo_pais (FK),
    prov_cod_actividad_economica (FK), prov_activo.

4. ESQUEMA "config" — PARÁMETROS GLOBALES, CONFIGURACIÓN Y AUDITORÍA
################################################################################
Gobierna la configuración de la aplicación, auditoría interna, mensajería,
parámetros institucionales, correos y procesamiento de texto (NLP).

--------------------------------------------------------------------------------
* TABLA: "config"."estado_suscriptor"
  - Modelo Django: EstadoSuscriptor
  - Descripción: Tipos de estado de cuentas de usuarios (1=Pendiente, 2=Habilitado, 5=Administrador, etc.).
  - Conexiones:
    <- "core"."suscriptor" (codigo_estado)
  - Campos principales: codigo_estado (PK, SmallAutoField), nombre_estado (VARCHAR(30) UNIQUE), descripcion.

--------------------------------------------------------------------------------
* TABLA: "config"."mensajeria"
  - Modelo Django: Mensajeria
  - Descripción: Anuncios globales y banners animados que se difunden en la cabecera del sistema.
  - Campos principales: id (PK, AutoField), asunto, cuerpo, estado (activo/inactivo),
    tipo_alerta (alerta/precaucion/exito), creado_el, actualizado_el.

--------------------------------------------------------------------------------
* TABLA: "config"."parametros_globales"
  - Modelo Django: ParametroGlobal
  - Descripción: Llaves y valores dinámicos del sistema (ej: umbrales de alerta de perfil).
  - Campos principales: codigo_parametro (PK, SmallIntegerField), nombre_parametro (VARCHAR(50) UNIQUE),
    valor_parametro, descripcion.

--------------------------------------------------------------------------------
* TABLA: "config"."info_contacto"
  - Modelo Django: InfoContacto
  - Descripción: Textos institucionales, enlaces y datos corporativos (Razón Social, RUT,
    teléfono, dirección y correo). Alimenta dinámicamente el footer, Centro Legal y formulario.
  - Campos principales: id (PK, AutoField), contacto_texto (TEXT),
    empresas_enlaces (JSONField - Arreglo de empresas, RUTs, direcciones y enlaces de contacto).

--------------------------------------------------------------------------------
* TABLA: "config"."configuracion_correo"
  - Modelo Django: ConfiguracionCorreo
  - Descripción: Direcciones de remitente, correo emisor de notificaciones y 2FA OTP,
    soporte y correo de auditoría de seguridad.
  - Campos principales: id (PK, AutoField),
    email_contacto (VARCHAR(255) - Soporte y canal comercial, ej: contacto@chileavanza.cl),
    email_notificaciones (VARCHAR(255) - Emisor de alertas y códigos OTP, ej: smartbids.qa@chileavanza.cl),
    nombre_remitente (VARCHAR(100), ej: 'SmartBids'),
    email_seguridad_auditoria (VARCHAR(255) - Auditoría técnica de inicio y bajas),
    actualizado_el (TIMESTAMPTZ).

--------------------------------------------------------------------------------
* TABLA: "config"."auditoria_admin"
  - Modelo Django: AuditoriaAdmin
  - Descripción: Bitácora inmutable de seguridad que audita cambios de roles, bloqueos o bajas entre administradores.
  - Campos principales: id (PK, BigAutoField), ejecutor_uid, ejecutor_email,
    ejecutor_nombre, afectado_uid, afectado_email, afectado_nombre,
    accion (VARCHAR(50): ELIMINACION, CAMBIO_ROL), detalle, creado_el, ip_origen.

--------------------------------------------------------------------------------
* TABLA: "config"."stop_word"
  - Modelo Django: StopWord
  - Descripción: Diccionario de palabras vacías (artículos, preposiciones, pronombres)
    para el procesamiento de lenguaje natural (NLP) en el motor de búsqueda y concordancia de licitaciones.
  - Campos principales: codigo_stop_word (PK, SmallAutoField), nombre_stop_word (VARCHAR(50) UNIQUE).


################################################################################
5. ESQUEMA "dw" — DATA WAREHOUSE (MODELO ESTRELLA PARA ANALÍTICA Y ML)
################################################################################
Almacena métricas consolidadas de millones de órdenes de compra históricas para
alimentar los paneles analíticos, rankings y los modelos predictivos de Machine Learning.

--------------------------------------------------------------------------------
* TABLA DE HECHOS: "dw"."fact_orden_compra"
  - Modelo Django: FactOrdenCompra
  - Descripción: Hechos transaccionales con métricas consolidadas de compras públicas.
  - Conexiones (Claves Foráneas hacia Dimensiones):
    * fecha_key -> "dw"."dim_fecha"
    * proveedor_key -> "dw"."dim_proveedor"
    * comprador_key -> "dw"."dim_comprador"
    * tipo_orden_compra_key -> "dw"."dim_tipo_orden_compra"
    * producto_key -> "dw"."dim_producto"
  - Métricas: monto_neto, impuesto, monto_bruto, cantidad_productos, precio_unitario,
    monto_item_pesos, monto_item_utm, cantidad_ordenes_compra, total_oc_procesadas.

--------------------------------------------------------------------------------
